# Python agent/retrieval chart

Disabled by default. Enabling requires `image` as a repository@sha256 digest, `sourceRevision` as the actual 40-character workload source commit and `existingSecretName`. The existing Secret must contain `lab-api-key` with at least 24 characters, as required by Settings. This chart creates/reveals no Secret value. Secure delivery/rotation and matching image-to-source provenance remain separately gated; Helm format checks do not establish them.

Explicit enable renders six objects in `ai-lab-dev` or `ai-lab-qa`: two tokenless ServiceAccounts, two ClusterIP Services and two Deployments for the existing agent/retrieval factories. Labels and ports match config's network contract. Faults are off; health probes use existing unauthenticated `/healthz`, which reports process/mock health rather than backend readiness. UID10001, seccomp, dropped capabilities, read-only filesystem, resource bounds and a 16Mi memory /tmp are declared. Config owns the namespace/policy; there is no Namespace, CRD, RBAC, Ingress, PVC, external Service or Azure resource.

Current Python code is deterministic-mock and explicitly labels telemetry environment `local`. Chart profile labels do not override that code or prove dev/qa attribution. The fixed retrieval/Collector DNS addresses and cluster.local assumption require target/network validation. No actual model endpoint or fallback is introduced; the future target remains AKS Python agents through APIM outside AKS, with Terraform-owned Azure/APIM and separate identities.

No published workload image is recorded yet. The checker generates clearly labelled `example.invalid` image references privately for offline render-contract tests only. They are not built/published images, rollout values or a release candidate; default enablement without real inputs fails. No fixture is promoted to GitOps. Image publication/replay, Secret delivery, pod startup/admission, identity/TLS/network and backend proof remain before rollout. Existing source/contracts/fixtures/locks/Dockerfile are unchanged.

Run `python scripts/check_application_chart.py --restore` for locked Helm lint/render and negative checks. `--restore` fetches only checksum-locked public tool bytes into a cache outside Git; offline checks require the cache. Read-only CI runs these checks alongside the existing tests/container build. No cluster/Azure call, registry publication, apply or sync occurs.
