# Private publication and Secret-delivery boundary

The user approved private GHCR publication. Only a manually dispatched, exact-SHA allowlisted workflow job can publish `ghcr.io/ai-sre-oberveability/ai-agent-workloads`. Normal push/PR jobs remain read-only. `POC_IMAGE_PUBLICATION_ENABLED`, `POC_IMAGE_WORKFLOW_SHA` and `POC_IMAGE_SOURCE_SHA` require explicit administrator setup; the script also verifies actor, repository ID, current main and its passing push CI. The allowlisted workflow may be on main or the named reviewed feature branch; application build source is always the separately pinned approved main commit. No PR source receives a package token. Close the temporary gate after the run. Never put an Azure identity or user PAT in this workflow.

Unique per-run tags are discovery pointers; consume the observed registry digest. The job checks private package visibility/repository association, source labels and pulled runtime platform. It uses ephemeral runner-only Docker configuration and GITHUB_TOKEN. No public-visibility mutation/deletion or global credentials are used. The receipt records source/workflow/run/image identities and a sanitized container authentication/rotation replay. It is not a signed SLSA attestation, vulnerability acceptance, seven-repo/backend release or AKS delivery proof; signing/scanning/retention decisions remain. The temporary discovery tag/package is retained as evidence; deleting it needs separate intent.

`contracts/secret-delivery.json` contains no values and authorizes no cloud operation. Terraform later owns Key Vault/AKS add-on resources, scoped identities/RBAC/networking, while secret values remain outside Terraform state. Key Vault CSI must mount a volume before sync to a namespaced Secret. The current app consumes env through SecretKeyRef; rotation requires coordinated/quiesced restart of agent and retrieval. Merely rotating a synced Secret does not refresh existing process environments. No production key or Azure IDs are generated here. Private GHCR pull credential delivery to AKS is still a separate design; do not copy the Actions token into a cluster.

Container replay uses fresh ephemeral synthetic keys stored only in mode-0600 private runner env files. It verifies health, authentication, deterministic citation behavior, faults-off, coordinated key rotation/old-key rejection and absence of both keys from captured logs. No values/hashes, env files or raw HTTP/log content enter artifacts or Git. This is a concrete container injection proof, not Kubernetes Secret/CSI/Workload Identity validation. Existing Python behavior and `local` telemetry attribution are unchanged.

Azure remains disabled. No Kubernetes/Azure login, resource, apply/sync or live-model call runs. Refer to the lab HLD/tracker and `docs/image-secret-delivery-plan.md`. Existing application/chart/profile inputs and GitLab/global Git settings are preserved.
